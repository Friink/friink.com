1. Overview
Friink is a software platform that combines community and a service marketplace. Focusing on mental health, it’ll provide a platform to interact with professionals and avail their services.
2. Auth
   1. Signup
      1. Users can sign up with a unique email address.
      2. Passwords must be at least 8 characters long and must include 1 uppercase letter, 1 lowercase letter, 1 special character, 1 number, and no spaces.
      3. 6 letter (alphanumeric) OTP will be sent for email confirmation.
      4. Username can contain only letters, numbers, ‘-’, ‘_’, ‘.’, and no spaces.
         1. Username must be unique.
      5. At the time of registration the user must be at least 13 years old based on the date of birth they enter.
      6. Location can be left empty at the time of registration.
      7. Email will be sent after successful registration.
   2. Login
      1. Users can login after registration with their email and password.
      2. OTP will be sent on registered email every time a user tries to login.
      3. Five consecutive failed attempts will lead to the account being blocked for 3 hours.
3. Users and Profiles
   1. Default User
      1. All users are default at the time of registration.
      2. Default users can create posts.
      3. Default users can like, star, quote, and share posts.
      4. Default users can request service.
      5. Default users can like, star, and share services.
   2. Professional
      1. A default user can get verified to become a professional.
         1. In order to get verified they’ll have to;
            1. Enter their legal full name.
            2. Provide a short introduction for the reviewer.
            3. Submit supporting documents.
         2. The application to become a professional must be reviewed by a human moderator.
      2. Upon verification a verified badge will be given to a professional user.
      3. Professional users have all the access given to default users, in addition they can also create services.
      4. Professional users will have to set their location.
4. Feed
   1. Home
      1. Posts from all users will be shown based on user profile and interactions.
   2. Connections
      1. Posts from followers and following will be shown here.
5. Post
   1. Create
      1. Any user can create a post.
      2. A post can have 512 characters.
      3. Users can attach media that must be compressed at the time of upload.
      4. Limit upload to 16 files max.
   2. Quote
      1. Using the quote button a user may create a quoted post.
   3. Share Internal
      1. Users can share posts via chat.
   4. Share External
      1. Users can share posts externally via link.
      2. Share external will only be available if a user allows external sharing.
      3. By default external sharing will be turned on.
6. Search
   1. Global
      1. Global search is available to every user.
      2. The search tab will let users search for other users.
         1. Users can search using part of usernames and names.
      3. The search tab will let users search for posts.
         1. Users can search for posts using phrases from posts.
         2. The search result can include results from users that don't have the search phrase in their post but in their username.
   2. Directory
      1. Users can access the directory from the side drawer.
      2. The Professionals tab will show professionals.
         1. Professionals will be sorted based on rating and location.
      3. The Services tab will show services.
         1. Services will be sorted based on professional rating, connection status, and location.
   3. Starred
      1. Users can access starred items from their side drawer.
   4. Chat
      1. Users can search for users and phrases in chat from messages.
7. Chat
   1. Messages
      1. Users can send text messages.
      2. Users can attach pictures, audio, and video files.
         1. The same data rules as post will be applied to attachment.
   2. Call
      1. Users can initiate a call from within chat.
         1. Calls can be audio and video.
      2. Users can share video while in a call to make it a video call.
         1. The user on the other side will get a prompt to convert a call into video call.
      3. Video calls will be used for service requests.
   3. Updates
      1. Some service request notifications will be sent via chat for redundancy.
8. Connections
   1. Followers
      1. A user will be added to flowers once they receive and accept a follow request.
   2. Following
      1. A user will start following another user once their follow request is accepted.
9. Service
   1. Create
      1. Professionals can make services.
      2. A service must have a title of not more than 128 characters.
      3. A service can have a description of not more than 256 characters.
   2. Request
      1. Any user can request service.
      2. Users can attach a note called “Request” while requesting.
         1. The note must not be more than 1024 characters.
      3. The request will have “New” status while it’s created and not opened.
      4. Once the provider opens the request it’s status will be updated to “Opened”.
      5. The professional can accept service, suggest another time, or decline.
         1. The status if accepted will be “Accepted”.
         2. The status if another time suggested will be “Pending”.
         3. The status will be “Declined” and then “Closed” if declined.
      6. Upon time agreement a payment link will be sent to the requester via email, chat, and notifications.
      7. Upon payment an event will be created and shown in the calendar to both provider and subscriber.
      8. If a request is declined and closed the user will get notified via email, chat, and notifications.
      9. Once the request is closed after being accepted, the provider will be able to add notes not more than 1024 characters.
      10. Once the request is closed after being accepted, the user will get an option to download details in a PDF file or share details both internally and externally via a link.
   3. Event
      1. An event will be created after successful payment.
      2. The event will be a video call scheduled in the calendar.
      3. If both participants miss the event, they will get an option to mark it done or request reschedule.
      4. No refund will be offered in case of missing the event.
      5. Refund policy? Tech issue?
   4. Tracking
      1. Request history will be saved and accessible in the service requests page for every request.
      2. In addition to statuses defined in 9.2, additional status will be;
         1. Event, when event is started either by provider or subscriber.
         2. Once both participants leave the event, the status will change to closed.
   5. Feedback
      1. Once an accepted request is closed, the subscriber will be asked to give feedback via notifications.
      2. The feedback will have an option to rate service and add comments, not more than 512 characters.
10. Calendar
   1. Month View
      1. The calendar will be the primary method to view events created upon service request acceptance.
      2. Users will be able to jump to dates using the calendar.
   2. Events
      1. The calendar will show a scrollable list of all events below the month.
         1. The list will default to the nearest upcoming event.
      2. Events will have a video call link embedded in the join button.
11. Notifications
   1. Push
      1. Users will be notified for;
         1. Likes on their posts.
         2. A user quotes their post.
         3. Comment on their post.
         4. Update on their service request.
         5. 15m before an event.
         6. Follow request.
         7. Someone unfollows them.
         8. Service request.
         9. Profile verification.
         10. Professional status revoked.
         11. Someone tries to login with their credentials.
         12. Successful login on another instance.
         13. Notes added to service request.
         14. Service feedback.
         15. Payment link generated.
         16. Payment successful.
         17. Failed professional verification.
         18. Event created.
   2. In App
      1. All the push notifications.
      2. In addition to push notifications;
         1. On the day of an event.
   3. Email
      1. Users will be notified for;
         1. Successful registration.
         2. Login attempt.
         3. Successful login.
         4. Service request creation.
         5. Service request update.
         6. Payment link created.
         7. Payment successful.
         8. Professional verification.
         9. Failed professional verification.
         10. Professional status revoked.
         11. Event created.
   4. Chat
      1. Users will be notified for;
         1. Service requests.
         2. Payment link.
         3. Event started.
